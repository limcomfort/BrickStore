# Фича: избранное и личный кабинет покупателя

## Проблема
Каталог из 12 наборов, но вернуться к присмотренному товару нельзя: нет списка,
нельзя сохранить между визитами. Заявки «Задать вопрос» уходят в CMS, но покупатель
не видит, что он спрашивал и что ему ответили.

## Решение
Личный кабинет без пароля: покупатель вводит имя и e-mail, система запоминает его
по cookie-сессии. В кабинете — избранные наборы и история своих заявок.

## Пользовательские сценарии

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| US-1 | Гость нажимает «В избранное» на карточке | Открывается короткая форма входа (имя + e-mail), после входа товар уже в избранном |
| US-2 | Покупатель убрал товар из избранного | Счётчик в шапке уменьшается, товар исчезает из списка без перезагрузки страницы |
| US-3 | Открыт `/account` | Видны избранные наборы и список заявок со статусом |
| US-4 | Покупатель выходит | Cookie удаляется, счётчик обнуляется |
| US-5 | Заявка отправлена с формы «Задать вопрос» | Заявка привязана к покупателю и видна в кабинете |

## Границы
**Входит:** избранное, вход по имени и e-mail, кабинет, привязка заявок, счётчики.
**Не входит:** пароли и восстановление доступа, оплата, корзина и оформление заказа,
e-mail-рассылки.

## Технические решения

- **Идентификация без пароля.** Отдельная коллекция `customers` с уникальным e-mail
  и случайным токеном сессии. Токен кладётся в `httpOnly`-cookie, браузерный JS его
  не читает. Публичного доступа к коллекции нет: покупатель видит только себя, через
  собственный API.
- **Избранное хранится на сервере**, в коллекции `favorites` (связь покупатель ↔ товар,
  уникальная пара). Так список переживает очистку cookie и виден в CMS.
- **Заявки получают связь с покупателем** — `inquiries.customer` (необязательная,
  чтобы старые заявки без аккаунта не сломались).

## Риски

| Риск | Реакция |
|---|---|
| По e-mail можно войти под чужим аккаунтом | Осознанное упрощение для учебного проекта; в требованиях зафиксировано. В продакшне — magic-link с подтверждением по почте |
| Перебор e-mail | Ограничение попыток входа по IP + задержка ответа |
| Cookie крадут через XSS | `httpOnly`, `sameSite=lax`, `secure` в продакшне |
| Рост числа заявок замедлит кабинет | Пагинация и составные индексы |

## Критерии приёмки

1. Гость не может прочитать чужое избранное через API — только своё.
2. Повторное добавление того же товара не создаёт дубль.
3. Избранное сохраняется после перезапуска сервера и очистки localStorage.
4. Кабинет показывает только заявки текущего покупателя.
5. `tsc`, `eslint`, `npm run build` проходят без ошибок.
6. Lighthouse на `/account` — не ниже 95 по доступности.
